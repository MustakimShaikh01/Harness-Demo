# Testing

```bash
pytest -q
python banking_agent/evaluation/evaluation_runner.py
cargo test --locked --manifest-path rust/audit-verifier/Cargo.toml
cargo fmt --manifest-path rust/audit-verifier/Cargo.toml -- --check
```

The Python suite covers beneficiary management, policy boundaries, transfer and bill-payment integration, ADK sensitive-tool confirmation configuration, cross-customer authorization, approval modification/expiry/replay, malformed JSON, money validation, prepared-journal recovery and audit-chain generation/tamper detection. Tests use temporary directories and do not call Gemini. Python and Rust both verify the shared fixtures in `tests/fixtures/`; Rust tests also cover streaming parse errors and trusted-head mismatch. CI additionally verifies an audit log generated by the Python logger with the Rust CLI.

The evaluation runner executes every pytest node ID linked in `banking_agent/evaluation/test_cases.json` and reports scenario-level outcomes. Prompt-safety checks validate instruction boundaries, not model resistance against every possible injection; this is not model-red-team certification. Live Gemini testing is separate and optional:

```bash
python scripts/smoke_agent.py
```

That script sends one short model request and can incur API usage.
